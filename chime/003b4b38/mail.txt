4) Consider youtube video "What is a Monad? - Computerphile" by Professor Graham Hutton (https://www.youtube.com/watch?v=t1e8gqXLbsU <https://www.youtube.com/watch?v=t1e8gqXLbsU> )?

	==> Consider he makes a good attempt to show the "Monad Pattern" of function + Effects composition by transforming division on Integers to division on Maybe-Integers?

	
	Original function that evaluates division

	
	The transform of divide into a "safe divide" that returns a Maybe-Int instead of an Int

	
	The modified evaluator that operates on our new "safe divide" (so we now have Maybe-Int as input and output) 

	
	Identifying the pattern "case Maybe-Int" into return of Nothing or f(Just x) 

So, the pattern we are looking at is that when we transformed our computation on Integers into computation on Maybe-Integers we had to add a step of examining the actual content of the input Maybe and only continue with the computation if it actually contain something. And using the Maybe-type we express "something" as being of Type "Just".

	
	Defining the sub-pattern "Nothing or f(Just x)" as "m sequenced with f" denoted with the ">>=" operator

	
	Abstracting our specific return "Just n" into general "return n" (thus our specific becomes return n = Just n)

	
	The division with Maybe-Int expressed with morphisms "return" and sequencing application ">>="

	
	Final computation using Haskel Do-notation

So in Haskel the Do notation is a short-hand for applying the sequencing operator to compose with computations on Maybe-Int (call next with the result of the previous one). The not so obvious but important observation is that the functions we actually compose with are those that take an Int but returns a Maybe-Int! These do not trivially compose as the output type does NOT macth the input type. But with the sequencing operator ">>=" they do! So what we have done is to first transform unsafe-division into safe-division by introducing an error-carrying option into the result type. Then solved the problem of composing with such functions using the special sequencing operator ">>=" that can deal with inputs of Maybe-Int and still utilise functions that operates in Ints. In this case the safediv was of type int->int->Maybe-Int so it kinds of "lifts" division of Ints to a level of Safe-Ints. On this "safe" level we can use "return" to get back a normal Int or continue with more computation using ">>=" and be able to utilise the "lifted" function Ints -> Maybe-Ints on any result in the sequence of computation.

So, the pattern we are trying to see is the "safe" level we can "get to and from" using a Monad! The Monad is the "thing" that provides the operations or computations required to compose with "lifted" computations. But it seems we need to recognise that the actual "lift" function must be provided separately. The Monad can NOT create that one for us. We had to choose to use the "Maybe" type and write the safediv that returns Maybe values and THEN provide that to the "Maybe Monad" to get to the "lifted" level of computation.
