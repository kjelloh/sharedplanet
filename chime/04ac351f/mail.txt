2) Now a Monad in is a special kind of “closed” category (there is no functor to leave the category)

	==> Consider a computer programming Monad (A monad of Sets and functions)

	==> All functors must map the category to itself so types can only transform between each other (such functors are called endo-functors)
	==> And any function composition must preserve an algebra of the source type in the target type.
	==> For example, if there is a ‘+’ operator defined for type T1, then any f: T1 -> T2 must perserve the ‘+’ relation between the values in T1 also in T2.
	==> I suppose one can understand this as the transformation is loss-less (the algebra holds and may be reversed through some g: T2 -> T1 gets us back)?
	==> Thus, a Functor must map all values in T1 to values in T2 and functions on T1 to functions in T2 - keeping the original relations between T1 values and T1 functions intact!
