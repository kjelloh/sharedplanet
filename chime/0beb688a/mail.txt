3) Consider how a C++ REPL IDE should behave?

	==> Consider a command line interface where input is C++ code that modifies the background Translation Unit?

		==> One can enter declarations and definitions and they will be entered into the background translation unit?
			==> Consider to show compiler errors in the entered code (never in dependent code)?
			==> Onside when and how to allow entered code affect dependent code?
			…

		==> Consider the background translation unit is stored as a clang generated AST in a Persistent Immutable Data Structure (always allowing for undo)?
		
			==> Consider to have dependent code be affected by changes only if the entered code compiles?
			==> Consider only user mutations of code counts as undo/redo steps (having automatically changes to dependent code be regarded as transactions following a successful user input)?
			==> Consider in this way the user may undo her/his input to come back to compiling code in just one undo?
			...

		==> One can enter imperative C++ instructions and they will be run?

			==> Consider how the background translation unit should be generated so that the application when run performs just the instructions the user entered?
			…

4) Consider the C++ REPL IDE should be just about entering declarations, definitions and statements (not writing an executable function)?

	==> Consider in this way the user may still write a complete application as long as it fits in calling one function (executing one statement)?
