Could it be a good idea to understand the SFINAE idiom and how and when to apply it to expose or hide members of the generated code?

1) Consider this article as a good start to understand the SFINAE idiom (https://en.wikibooks.org/wiki/More_C%2B%2B_Idioms/SFINAE <https://en.wikibooks.org/wiki/More_C++_Idioms/SFINAE>)?

	==> SFINAE seems to be an abbreviation for ”Substitution Failure Is Not An Error”?

	==> The idiom seem to exploit the fact that a failure to instantiate a template specialization candidate is not an error?

		==> Invalid returns type of template function or method is not an error (simply ignored as candidate)
		==> Invalid template function or method parameter is not an error (simply ignored as candidate)

”If an invalid argument or return type is formed during the instantiation of a function template, the instantiation is removed from the overload resolution set instead of causing a compilation error. As long as there is one and only one function to which the call can be dispatched, the compiler issues no errors."
	
		==> In this example the template candidate fails to instantiate as client call uses parameter type int that does not have member ”multiplication_result” and thus the template function return type is illformed. 

long multiply(int i, int j) { return i * j; }

template <class T>
typename T::multiplication_result multiply(T t1, T t2)
{
  return t1 * t2;
}
int main(void)
{
  multiply(4,5); // template multiply<int> discarded as return type int::multiplication_result is invalid

}
”
Calling function multiply in main causes the compiler to instantiate the signature of the templatized function even though the first multiplyfunction is a better match. During instantiation an invalid type is produced: int::multiplication_result. Due to SFINAE, however, the invalid instantiation is neglected automatically. At the end, there is exactly one multiply function that can be called. So the compilation is successful.
"	

		==> This seem to be an example of two step template instantiation based on SFINAE selected constructor return type?

template <class T>
struct is_pointer
{
  template <class U>
  static char is_ptr(U *);

  template <class X, class Y>
  static char is_ptr(Y X::*);

  template <class U>
  static char is_ptr(U (*)());

  static double is_ptr(...);

  static T t;
  enum { value = sizeof(is_ptr(t)) == sizeof(char) };
};

			==> It is a meta-function returning type dependent value (evaluates to true if matched constructor returns a type of size char)?

				==> Constructor instantiation uses SFINAE to select only the one matching the instantiation parameter T to  constructor parameter expression

					U*		==> matches pointer to U
					Y X::*	==> Matches member X pointer
					U (*)())	==> Matches function pointer (function taking no parameters)

template <class T>
