4) Consider Monads as functors that lifts the category iof types and functions to a Category of ”Monadic” (lifted) values and functions?

	==> Consider the Monad Optional lifts a Category of types to a Category of Optional types?

		

		==> Optional<T> lifts object T (type) to object Optional<T> (also a type)
		==> Optional::bind lifts ”diagonal” functions from T1 to Optional<T2> to the Monoidal function Optional<T1) to Optional <T2>

		==> Hm… It is still a bit awkward where we get the Diagonal Function from (do they occur naturally and the Monad makes the composable)?  

	==> Now it seems the Category of objects being Monads are in fact the same as the Monoids in the Category of Endofunctors?

		

		==> Monads are Endofunctors because if we apply the Monad Functor to its own category we are still in the same category?

			Optional<Optional<T>> == Optional<T>
			List<List<T>> == List<T>
			Future<Future<T>> == Future<T>
			…

		==> And binary composition of Monadic Values are the new Monadic Values of the same type (the same object)

			Optional<T> + Optional<T> == Optional<T>
			List<T> + List<T> == List<T>
			Future<T> + Future<T> == Future<T>
			...
