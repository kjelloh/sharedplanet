I find it really annoying that most Users Manual starts bottom-up and in chronological order rather that in order of interest?

1) Consider a Users Manual should start of with what you can do and how you should do it?

==&gt; Consider to relate this as if the Tool provides a World of objects and entities?

2) Consider how Building from source, Installation and configuration should be way back in appendix (used only once)?

3) Consider how important it is for a Users Manual to define the usage experience (how to use rather than how it works)?

==&gt; Consider that how the tool does stuff is of low interest to the normal user?  
==&gt; Consider that the user what’s tu understand “the world” the tool exposes (concepts, models and how to interact with it)?  
==&gt; Consider to use a Text Editor as an example?  
==&gt; A Text Editor provides a “world” of Documents, pages, paragraphs, Headings etc.  
==&gt; In this world the user is able to interact with the objects and entities of this world?  
==&gt; Entities (actors) can be Search-and-replace, macros and other stuff that can be engaged as agnets of the user?

4) Consider any application to provide a user interface of objects, space-and-time and “Entities” (actors)?

==&gt; Consider objects to be passive “things” in the world created by the application (e.g. paragraphs in a Text Editor World)?  
==&gt; Consider Entities to be active agents that can manipulate objects in the world on behalf of the user (e.g. Search-and-replace in a Text Editor World)?

Consider to elaborate on this idea of Software Applications can actually be seen as creating a World of Objects and Entities in which the user may engage to get some specific work done?
