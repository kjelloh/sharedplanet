1) Consider the Yaml “Yet Another Markup Language” data representation encoding (https://en.wikipedia.org/wiki/YAML <https://en.wikipedia.org/wiki/YAML>)?

	==> Yaml seems to define a basic set of types called “scalars”?

“YAML natively encodes scalars (such as strings, integers, and floats), lists, and associative arrays (also known as hashes or dictionaries"

	==> And these are based perl scalar types?

“These data types are based on the Perl programming language, though all commonly used high-level programming languages share very similar concepts. YAML supports both Python-style indentation to indicate nesting, and a more compact format that uses [] for lists and {} for hashes"

	==> Yaml seem to support both its own (python like indentation encoding) and Json style composition syntax for lists [] and {} for objects (in yaml called hashes)?

“YAML supports both Python-style indentation to indicate nesting, and a more compact format that uses [] for lists and {} for hashes"

	==> Consider this page for the definition of Perl (Yaml) basic data types (https://www.tutorialspoint.com/perl/perl_data_types.htm <https://www.tutorialspoint.com/perl/perl_data_types.htm>)?

“Perl has three basic data types: scalars, arrays of scalars, and hashes of scalars, also known as associative arrays"

		==> Note that arrays and hashes does not seem to nest?

	==> Consider this official Yaml page on the syntax (http://www.yaml.org/spec/history/2001-12-10.html <http://www.yaml.org/spec/history/2001-12-10.html>)?

		==> Yes, in Yaml the structures (collections) do nest.

“YAML collections allow for aggregation of data. There are two primary types of collections which YAML supports, sequences and mappings. Most tree structures can be constructed by nesting collections."

5) consider ASN.1 “Abstract Syntax Notation One” (https://en.wikipedia.org/wiki/Abstract_Syntax_Notation_One <https://en.wikipedia.org/wiki/Abstract_Syntax_Notation_One>)?

	==> It seems ASN.1 is a kind of “language” that defines protocols data exchange encoding as well as exchange rules?

“Protocol developers define data structures in ASN.1 modules, which are generally a section of a broader standards document written in the ASN.1 language. Because the language is both human-readable and machine-readable, modules can be automatically turned into libraries that process their data structures, using an ASN.1 compiler."

		==> It seems ASN.1 “code” aims at being readable to both humans and ASN.1 compilers?

	==> Consider this list of free online downloadable books about ASN.1 (http://www.oss.com/asn1/resources/books-whitepapers-pubs/asn1-books.html <http://www.oss.com/asn1/resources/books-whitepapers-pubs/asn1-books.html>)?
