The more I delve into the world of functional programming and Persistent (Immutable) Data Structures it seems to me that the Darwinet MIV is actually a Confluent Persistent Data Structure and we may thus implement it using solutions available in C++ or other languages where these data types already occur?

1) Consider good talks on the subject?

	==> Consider this seemingly really good lecture ”1. Persistent Data Structures, MIT OpenCourseWare” (https://www.youtube.com/watch?v=T0yzrZL1py0 <https://www.youtube.com/watch?v=T0yzrZL1py0>)

		==> The lecture is about Partially and Confluent Persistence and touching on Functional Data Structures.
		==> They are mostly about concepts and cost (not about actual implementation)
		==> In Functional Persistence we require old versions to be referentially the same (change requires references to change) while basic persistence only require ”query equality” (same query returns same result in perserved state)
		==> At 23:50 he actually defines a ”modification” as (version, field, value) which is exactly a MIV Delta (state, element path, operation) :)
		==> At 1:04:30 he starts on Confluent Persistence.

		==> All lectures in the same course ”Advanced Data Structures” seems to be here (https://ocw.mit.edu/courses/electrical-engineering-and-computer-science/6-851-advanced-data-structures-spring-2012/lecture-videos/ <https://ocw.mit.edu/courses/electrical-engineering-and-computer-science/6-851-advanced-data-structures-spring-2012/lecture-videos/>)?
