1) This seem to be a good starting point to understand this beast (http://www.cprogramming.com/c++11/c++11-compile-time-processing-with-constexpr.html <http://www.cprogramming.com/c++11/c++11-compile-time-processing-with-constexpr.html>)?

	==> It seems constexpr expressions is evaluated at compile time if possible - otherwise it is turned into a runtime expression?

	==> If all code and data is known at compile-time it is compile time evaluated?

	”A constexpr function has some very rigid rules it must follow:

		• It must consist of single return statement (with a few exceptions)
		• It can call only other constexpr functions
		• It can reference only constexpr global variables”

	”A constexpr function can have only a single line of executable code, but it may contain typedefs, using declarations and directives, and static_asserts.”

	==> It is turned into a run-time evaluated expression if provided with data known only at run-time?

	”A function declared as constexpr can also be called at runtime if the argument to the function is a non-constant”

	==> One may ”construct and call” class objects by declaring applied constructors and methods  as constexpr?

class Circle
{
    public:
    constexpr Circle (int x, int y, int radius) : _x( x ), _y( y ), _radius( radius ) {}
    constexpr double getArea () 
    {
        return _radius * _radius * 3.1415926;
    }
    private:
        int _x;
        int _y;
        int _radius;
};

constexpr Circle c( 0, 0, 10 );
constexpr double area = c.getArea();
	”First, we need to declare the constructor as constexpr, and second, we need to declare the getArea function as constexpr”

	==> consexpr variables and functions are run-time const buy default. But const variables and functions are NOT constexpr by default.

	==> constexpr expressions may use floating point types whereas Template Functions may not (Template Value Parameters may be integer compatible only, e.g. int and bool)

2) This seem like a good introduction from cppcon 2015 about constexpr (http://clang-developers.42468.n3.nabble.com/Review-CLion-a-great-way-to-develop-on-clang-td4043928.html <http://clang-developers.42468.n3.nabble.com/Review-CLion-a-great-way-to-develop-on-clang-td4043928.html>)?

	==> constexpr kind-of asks of the compiler to run a c++ “interpreter”.
	==> In C++11 the standard says what you CAN do (heavily constrained)

		==> single statement only (sub-statements ignored)
			==> Enables code ok only at run-time (as long as it does not evaluate at compile-time)
			==> An example is having throw in constexpr (ok as long as the throw does NOT evaluate at compile-time)
		==> ternary operator allowed (enables recursion through return <predicate>?<recurse_call>:<terminate_expression>;)
		==> Only literal types or refs to literal types.

	==> In C++14 the standard says what you CAN’T DO (less constrained)
		==> Means in C++14 the standard lists what the interpreter does not know how to interpret.

	==> He shows an C++14 example of compile-time string manipulation (char arrays)

	// Can’t use C++14 std::array, since element access is not defined as constexpr.
	template <typename T, std::size_t N>
	class array_result {
	private:
		constexpr static std::size_t size_ = N;
		T data_[N]; // T must have a default constructor (a constexpr one to enable use of this code in constexpr statements) 
	public:
		// …
		constexpr T& operator[] (std::size_t n) {
			return data_[n];
		}
		using iterator = T*;
		constexpr iterator begin() {return *data_[0];}
		constexpr iterator end() {return &data_[N];}
		// …
	}

	template <std::size_t N> 
	constexpr auto constexpr_to_upper (const char(&in)[N]) 
		-> array_result<char, N> 
	{
		array_result<char, N> out; 
		for (Std::size_t i = 0; in[i] != 0; ++i) 
		{
			char c : in[i]; 
			out[i] = ((c < ’a') II ( c > ’2'))? 
				c : c - ('a' - ’A'); 
		}
		return out;
	}

	main {
		static constexpr auto a = 
			constexpr_to_upper(“Frank Lloyd Wright”);
		// a will be compiled to hold “FRANK LLOYD WRIGHT"
	}

	==> Uses user-defined array_result template to store constexpr array result
		==> array_result is a templatetized class with constexpr members.
		==> member size_ is static (each template instantiation will be a unique class type)
		==> Q: Why is not member data_ constexpr static?
