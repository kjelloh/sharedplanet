	==> Model seems to be a type alias (i.e., a type)?	

		type alias Model = {…}

	==> Update seems to be a function that accepts a Msg and a Model and create a new Model?

		Update : Msg -> Model -> Model

	==> And View transforms a Model to Html (that produces Msg and pass to update)?

		View : Model -> Html Msg

		==> The syntax Html Msg is strange (but seems to mean a Html value that is able to produce Msg values?

””

	==> The binding between the Html value and the a Msg value seems to be made in the view method (that generates the Html value)?

”One thing to notice is that our view function is producing a Html Msg value. This means that it is a chunk of HTML that can produce Msg values. And when you look at the definition, you see the onClick attributes are set to give out Increment and Decrement values. These will get fed directly into our update function, driving our whole app forward."

		==> Consider an example of a view implementation

view : Model -> Html Msg
view model =
  div []
    [ button [ onClick Decrement ] [ text "-" ]
    , div [] [ text (toString model) ]
    , button [ onClick Increment ] [ text "+" ]
    ]
		==> It seems to generate html code using Elm functions like ”div” and ”button”?

”Another thing to notice is that div and button are just normal Elm functions. These functions take (1) a list of attributes and (2) a list of child nodes"		


3) Elm seems to use separate function declaration and definition?

	==> Also see ”Todo: Meta Value Model - Consider ways to implement function meta-value hierarchy (meta-2...meta-0 declaration, definition operations)?"

	==> The function declaration defines function name and mapping?

	Elm> Update : Msg -> Model -> Model	// Reads: Identifier ”update” is of meta-value Msg -> Model -> Model

		==> Which would mean our Meta Value Lisp declaration could be:

		meta-0> (declare Update (function Msg Model Model))

	==> The function definition seems to declare arguments and define the function body?

	Elm> Update msg model = … function body …

		==> Which would mean our Meta List definition would be:

		meta-0> (define Update msg model (… function body…))

		==> Note: It seems we can’t apply the function identifier as value constructor as this would would be confused with function application (how would evaluator know when to execute constructor and when to execute actual function)?
