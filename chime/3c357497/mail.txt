3) Consider a visitor pattern to enable a scripting engine to operate on the model?

	==> Consider the scripting engine must parse the script into declare/define operations?

		(: count number) 	// declares name count as meta-value number
		(= count 4)		// defines name to value 4

	==> Consider Lisp-style where a list always evaluates to first-element as-function applied to the list-tail as-values)?

		==> A list value = list-head applied to list-tail?
		==> An identifier value = its bound value?

	==> Consider what this means to implement scripting of declarations and definitions?

		Declaration:	 (: name meta-value)
		Definition:	(= name value)

		==> Would indicate we need to have scripting engine implement ’:’ and ’*’ functions?

	==> Now, we have proposed a meta-value is a function that creates values?

		==> Thus Declaration = meta-value applied to initializer value list?

			meta_value.apply(initializer-value-list)

	==> And we already defined the lisp scripting language to be only nested list-values and identifier values?

		evaluate script := evaluate(list) | evaluate(identifier)

		evaluate(list) := apply(list.head, list.tail)
		evaluate(identifier) := identifier.as_value

		apply(head,tail) := head.as_function(tail)

		
	==> Consider ”declaration” to be a meta-value with as_function to create an Identifier?

		==> I.e., declare defines the Set {Identifiers}?

		(declaration count number) would translate to apply(declaration.as_function,{”count”, ”number”} instantiating a Declaration{”count”, ”number”}

	==> But then, how to we define the layer to hold that value?

		==> We would need the layer to be a list of identifiers?
		==> And we would need to define an append method (lisp built-in function)?
