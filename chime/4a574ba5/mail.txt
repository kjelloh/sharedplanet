1) A Strongly Connected Component is one of Nodes that only refers to other nodes wishing the component (https://en.wikipedia.org/wiki/Tarjan%27s_strongly_connected_components_algorithm <https://en.wikipedia.org/wiki/Tarjan's_strongly_connected_components_algorithm>)

	==> Consider that groups of functions and classes that only references each other are subjects for library components?
	==> Q: Dows this include components that uses call-backs?
		==> Yes - it only means that the call-back interface is part of the SCC?
		==> And it will be as C++ wont compile unless all types are known?

	==> Consider that SCC detection must be able to identify both Template Components and run-time components?
		==> A SCC of Templates takes types as inout but still only contains internal references using provided types and internal types?
		==> An SCC with no exposed templates only uses runtime provided parameters?

	==> It seems we must be able to detect library boundaries of Compile time Interfaces (Template Parameters) and runtime interfaces (value parameters)?
