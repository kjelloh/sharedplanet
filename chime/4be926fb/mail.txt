Could it be a good idea to implement a C++ make script factory that the make environment calls to get the make script to execute?

1) Consider a make script factory being able to analyze existing source code and generate the appropriate make script to build possible targets?

	==> Consider a command line environment may stream the make script to the make utility using a command line make script factory application?

		>make_factory > make

	...

2) Consider a makes script factory being able to provide different pieces of a make script (e.g. the list of source files)?

	==> Consider a make script factory could be queried for possible targets to build (it being able to generate possible targets by analyzing the source code)?
	==> Consider a mek script factory could provide a list of source files to compile for a defined target (the client provides the target in the query for files)?
	==> Consider a make script factory could be queried to provide possible #ifxxx switches (available source code profiling options)?
		==> Co insider it should be able to produce a list of pre-processor switches and the ”decision points” for each switch (e.g., #ifdef MY_OPTION defined/undefined)?

3) Consider a make script factory could also be combined with a source file (translation unit) producer?

	==> Consider a source file producer  could generate source files from a source file database (no need to store the actual source files)?
	==> A source file producer could free the programmer from having to define actual source files (only write types, classes and methods)?
