Could it be a good idea to discuss how we may free the C++ programmer from burden of having to deal with source files?

1) Consider source files are just a necessary-evil to implement persistent storage and address compiler memory restrictions?

	==> From a programmers point of view we don’t need ”files”, we need code-snippet dependency protection.

2) Consider a C++ programming model where we only work with C++ code components (not translation units)?

	==> Can we imagine an automatic phase that generates translation units from the source code written by the programmer?
	==> Consider the programmer works only with ”code-snippets” (functions, templates, bracket-scopes, control-statements etc.)

		==> The automated ”translation unit assembly” phase than generates the most optimal source code files to feed to the compiler?
		==> The programmer does not need to bother with what files are actually feed to the compiler?
		…

	==> Consider if this idiom can still be made to fit into existing text-file based source code writing tools?

		==> Q: Do we need a special IDE to write code in this way?
		==> Q: Or can we provide a ”virtual source file world” to have the programmer work as usual (although the actual files feed to the compiler are not the one written by the programmer)?

3) Consider how this ”translation unit file generator” maps to the Modules-proposal?

	==> Can we imagine the C++ Modules-proposal can be made to fit this auto-source-file idiom?
	…

4) Consider this ”translation unit file generator” can be made to replace current pre-processor functionality?

	==> Consider the benefits of ”translation unit file generator” is C++ Language aware (while the pre-processor is not)?
	==> Consider the ”translation unit file generator” can be made to perform some parts of what the Template-mechanism in C++ does?
	…

5) Consider that this ”translation unit file generator” can be applied so that it separates compile-time code generation from actual run-time code generated by the compiler?

	==> Thus having the ”translation unit file generator” processing every part of the compile-time code generation?
	==> Consider how this may fit C++17 and C++20 projections of where the language is going and how we may aid to get compile-time generated code more separated from run-time code?

	==> Consider we may aim at having a clear line so that ”translation unit file generator” generates code to compile and the compiler generating code to run?
	…

…

Consider to delve into this idea of how to make a C++ programmer not having to think about source files and how this may be made to also separate compile-time code generation from compiler generated run-time code?
