	==> Consider good leads on this video size calculator (https://www.omnicalculator.com/other/video-frame-size#how-to-calculate-the-video-frame-size <https://www.omnicalculator.com/other/video-frame-size#how-to-calculate-the-video-frame-size> )?

		==> It seems the frame size in bytes are simply Pixel Count x Pixel Colour bit depth?

"The higher the color depth, the bigger the data size of every pixel. If you use 8-bit colors, each pixel has to store 8 bits of information (equivalent to 1 byte <https://www.omnicalculator.com/conversion/byte-converter>). 16-bit colors need 2 bytes of information per pixel, 24-bit need 3 bytes.
Once you know the resolution and color depth, you can find the frame size according to the following equation:

frame size = V * H * CD

where

V is the vertical resolution,
H is the horizontal resolution, and
CD is the color depth." 
		==> And then uncompressed video is simply the frame size times the frame rate times the length of the video?

"video size = frame size * fps * time
where

time is the duration of the video, and
fps is the number of frames displayed per second. This number can range from 12 fps to even 60 fps; the most common value, however, is 24 frames per second."

	==> Consider the "Kush Gauge Equation" for determining a somewhat subjective but good enough bit rate requirement for a wanted "quality" of a H.264 compressed video?

"After numerous experiments, I noticed a certain pattern of what could be considered a “constant” or base
value (for most commonly used video frame-size and frame-rate ranges). When rounded
off, that value is 0.07 bps per pixel, per frame, per motion rank value.
In other words, to estimate the optimal H.264 bit rate value that would give what is
considered “good quality” results for a given video, you could multiply the target pixel
count by the frame rate; then multiply the result by a factor of 1, 2 or 4, depending on its
motion rank; and then multiply that result by 0.07 to get the bit rate in bps"

"Practical example
1280 Å~ 720 @24fps, medium motion (rank 2):
1280 Å~ 720 Å~ 24 Å~ 2 Å~ 0.07 = 3,096,576 bps = ~ 3000 kbps
If the motion is high (rank 4), it’s about 6000 kbps.
On the other hand, if the same clip is still usable at 5fps, and the motion is low:
1280 Å~ 720 Å~ 5 Å~ 1 Å~ 0.07 = 32,256 bps = ~ 320 kbps
A reduction in frame size can dramatically reduce the bit-rate requirements:
640 Å~ 360 Å~ 5 Å~ 1 Å~ 0.07 = 80,640 bps = ~ 80 kbps"
