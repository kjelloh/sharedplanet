(2) Consider C++ templates can be modeled as generic type-constrctors dispatched on template arguments?

	==> In this way templates are just generic functions ”called” with template arguments and dispatched to matched instantiation?

	==> We then can apply pattern matching to pick the best candidate given the provided template arguments?

	==> So, how can we model C++ templates as higher-meta functions?

		==> consider template is the top-function?
		==> It instantiates type-constructors (i.e., class, function or alias templates)
		==> Then ”template” identifier is defined on meta-3 (!) ??

		==> NO! template instantiations are meta-1 generic types!

		meta-2:	Identifier {”template” , template<3> } = Set {…any template<1> …}
                                                                                                                 |
                                                                    --------------------------------------
                                                                     |      (as_function args definition<1>) (e.g. template <…args> class {}, template <…args> T f(T) {}, template <…args> using name = T)
                                                                     v
		meta-1:	Identifier {”name” , template<2> } = Set {…any template<0> …} GENERIC meta-1 values
                                                                                                                 |
                                                                    --------------------------------------
                                                                     |      as_function args to define meta-0 value (i.e., the type constructor)
                                                                     v
		meta-0:	Identifier {”name” , template<2> } = Set {…any template<1> …} GENERIC meta-0 values (C++ executable)
