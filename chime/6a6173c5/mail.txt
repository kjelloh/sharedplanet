1) Consider this wikipedia page on Closures (https://en.wikipedia.org/wiki/Closure_(computer_programming) <https://en.wikipedia.org/wiki/Closure_(computer_programming)> )?

	==> It seems a closure is a record aggregating an environment with a function (binding function body free variables to the environment)?

“ Operationally, a closure is a record storing a function together with an environment: a mapping associating each free variable of the function (variables that are used locally, but defined in an enclosing scope) with the value or reference to which the name was bound when the closure was created.[b] A closure—unlike a plain function—allows the function to access those captured variables through the closure's copies of their values or references, even when the function is invoked outside their scope."

	==> Consider we shall stick with the term “value” both for data and code (as in functions)?

“...both a and b are closures—or rather, variables with a closure as value—in both cases produced by returning a nested function with a free variable from an enclosing function, so that the free variable binds to the parameter x of the enclosing function."
“Note especially that the nested function definitions are not themselves closures: they have a free variable, which is not yet bound. Only once the enclosing function is evaluated with a value for the parameter is the free variable of the nested function bound, creating a closure, which is then returned from the enclosing function."

template <typename... FArgs>
struct environment {
  std::tuple<FArgs...> members;
  environment(FArgs... args) : members{args...} {}
};

template <typename... FArgs>
struct closure {
  environment<FArgs...> e;
  closure(FArgs... args) : e{args...} {}
};

struct my_closure : public closure<int> {
  my_closure(int k) : closure{k} {}
  int operator()(int x) {
    return (x*x)+std::get<0>(e.members); // models f x = x*x + k
  }
};

int main(int argc, const char * argv[]) {
  my_closure mc{2};
  std::cout << '\n' << "my_closure(4) = {4*4 + 2} " << mc(4);
  std::cout << std::endl;
  return 0;
}

2) Consider this wikipedia page on lambda calculus (https://en.wikipedia.org/wiki/Lambda_calculus <https://en.wikipedia.org/wiki/Lambda_calculus>)

	==> It seems lambda calculus is about lambda terms and how to reduce them into (values?)

Lambda calculus consists of constructing lambda terms and performing reduction operations on them. In the simplest form of lambda calculus, terms are built using only the following rules:
Syntax	Name	Description
a	Variable	A character or string representing a parameter or mathematical/logical value
(λx.M)	Abstraction	Function definition (M is a lambda term). The variable x becomes bound in the expression.
(M N)	Application	Applying a function to an argument. M and N are lambda terms.


	==> It seems there are two ways to reduce lambda terms?
The reduction operations include:
Operation	Name	Description
(λx.M[x]) → (λy.M[y])	α-conversion	Renaming the bound (formal) variables in the expression. Used to avoid name collisions <https://en.wikipedia.org/wiki/Name_collision>.
((λx.M) E) → (M[x:=E])	β-reduction	Substituting the bound variable by the argument expression in the body of the abstraction

		==> alpha conversions seems to be about renaming variables in abstractions (variable “x” in an abstraction can be converted into equivalent abstraction using variable “y”)?
		==> Beta conversions seems to be about replacing a variable bound in an expression with the body of the bound expression (e.g., f(x) : x*x in f(x)*2 becomes (x*x)*2)?
		…

	==> It seems the syntax M[…] is used to apply operations to members of M (e.g. M[x] refers to x-bindings in M and M[x:=E] refers to replacement of all x with E within M)?
