2) It seems the way to ensure local clone exactly mirrors the remote is to git fetch and then git reset —hard origin?

	==> The git fetch seems to just update the local copy of the remote state (all commits updated according to the remote)
	
C:\Users\kjell-olovhogdahl\Documents\GitHub\msm-lite [master ↑]> git fetch

	==> The git reset —hard just re-sets the HEAD to the last commit (restoring the working file)

C:\Users\kjell-olovhogdahl\Documents\GitHub\msm-lite [master ↑]> git reset --hard
HEAD is now at 05d8b49 Test that accidental changes to cloned rep does not Github Desktop Sync back to the remote?

	==> Providing the reference “origin” will re-set the HEAD to the last commit of the remote (origin is just an alias to the HEAD commit of the remote copy)?

C:\Users\kjell-olovhogdahl\Documents\GitHub\msm-lite [master ↑]> git reset --hard origin
HEAD is now at 5dd2691 [thread-safety] Added mutex for thread safe process_event
C:\Users\kjell-olovhogdahl\Documents\GitHub\msm-lite [master ≡]>	

		==> The locally changed (but not committed) working file was now silently replaced with the HEAD of the last fetched remote.

3) It seems Github Fork is not the way to just use another Github repository?

	==> When one forks a project in Github it is cloned to ones account as a new repository but with meta-data to remember where it was forked from?

	=>= A fork behaves just as any repository but the local clone uses the Github repository with the fork (NOT the original repository we would like to track and use)?

	==> To delet a fork one has to delete the repository of the fork.

		==> First enter the repository that contains the fork.
		==> In the URL add “/settings” (e.g., to get “https://github.com/kjelloh/tree/settings”
		==> Then scroll down to “Danger Zone” settings and click “Delete this Repository"


		

		==> Follow the instructions to delete the repository.
