1) Locally Git seem to store a local copy of the whole project repository with all the change history (https://git-scm.com/blog/2010/04/11/environment.html <https://git-scm.com/blog/2010/04/11/environment.html>)?

	“... just one .gitdirectory in the root of your project.”

	==> The “.git” local folder seems to be the “repository” (https://git-scm.com/book/en/v2/Git-Basics-Getting-a-Git-Repository <https://git-scm.com/book/en/v2/Git-Basics-Getting-a-Git-Repository>)?

	“You can get a Git project using two main approaches. The first takes an existing project or directory and imports it into Git. The second clones an existing Git repository from another server.”

	==> Sidenote: Already here a newbie will be confused as to what is a “project”, what is a “Repository” and what is a “Directory”?

2) Consider this site to find leads to Git concepts (https://www.sbf5.com/~cduan/technical/git/git-1.shtml <https://www.sbf5.com/~cduan/technical/git/git-1.shtml>)?

	“The purpose of Git is to manage a project, or a set of files, as they change over time. Git stores this information in a data structure called a repository.”

	“The Git repository is stored in the same directory as the project itself, in a subdirectory called .git. Note differences from central-repository systems like CVS or Subversion:

		• There is only one .git directory, in the root directory of the project.
		• The repository is stored in files alongside the project. There is no central server repository.”

	“A git repository contains, among other things, the following:

		• A set of commit objects.
		• A set of references to commit objects, called heads.”

	“A head is simply a reference to a commit object. Each head has a name."

	“A commit object contains three things:

		• A set of files, reflecting the state of a project at a given point in time.
		• References to parent commit objects.”

	==> Side note: A Git Commit seem to correspond to a Darwinet Delta (parent defines the previous state or states in case of a merge)?


“---->  time  ----->

(A) <-- (B) <-- (C)
                 ^
                 |
               master
                 ^
                 |
                HEAD

			where (A), (B), and (C) are the first, second, and third commits, respectively.”

		==> Seems “HEAD” is the reserved name of the current head (in effect the current state of the project as defined by the commit HEAD is referencing?

	==> Seems if we only work locally we may create a git project/repository in any folder using “project-folder>git init”?

“	>mkdir [project]
	>cd [project]
	>git init

This will create a .git directory in the [project] directory."

	==> 	Consider this page to understand branching (https://www.sbf5.com/~cduan/technical/git/git-2.shtml <https://www.sbf5.com/~cduan/technical/git/git-2.shtml>)?

	“The terms “branch” and “head” are nearly synonymous in Git. Every branch is represented by one head, and every head represents one branch.”

	==> Seems “head” (referencing a “commit”) corresponds to darwinet “state” in a delta-trail?

“(A) -- (B) ------- (C)
        |           |
   fix-headers    master
                    |
                   HEAD”

		==> Seems the “branch” fix-headers is simply a named “head” currently referencing the (B) commit?
	
	==> Seems “git branch” just creates a named “head” (in effect enabling commits to use the named head as parent)?

		==> Syntax seem to be "git branch [new-head-name] [reference-to-(B)]”

	>git branch fix-headers HEAD^

		==> Seem to mean create named head “fix-headers” and make it refer to the parent of the commit referenced by current HEAD (See tree above)?

	==> Seems “git checkout” sets the commit the HEAD references and updates the local folder file states as defined by the state of that commit?

	>git checkout fix-headers

         ------------------
        /                 |
(A) -- (B) -- (C)         |
               |          |
             master   fix-headers
                          |
                         HEAD

	>git commit -a

“         +-------------- (D)
        /                 |
(A) -- (B) -- (C)         |
               |          |
             master  fix-headers
                          |
                         HEAD"

		==> Seems “git commit” stores a new commit object (D) an links it into the trail of commits ( D-parent set to B and fix-headers set to D)
