    Generic Elm run-time System Model
 
         ---------------------------------------------------------------------------------
         |                                                                               |
         |  Asynchronous IO    Declares: Model, Msg {msg_1…msg_n} and View               |
         |         |           Defines: subscriptions, update and view                   |
         |         v                                                                     |
         |   subscriptions                 update                       view             |
         |        ^|                         ^|                          ^|  Application |
         ---------||-------------------------||--------------------------||---------------
                  ||                         ||                          ||
                  ||                         ||                          ||
                  || (5.2)               0.1 || (1)                (1.2) || (2)
            (4.2) || { Model     { Model 6.1 || { Mod Model  {Mod Model} || { View
         { Model  ||  ,Sub Msg}   ,Msg}  6.2 ||  ,Cmd Msg}               ||  ,Op Msg}
          ,Msg}   |v                     1.1 |V                          |v
         ---------------------------------------------------------------------------------
         |                                                                      run-time |
         |                      Declares decorators: Mod, Sub, Cmd, Op                   |
         |      run             defines: run                                             |
         |       ^                                                                       |
         --------|------------------------------------------------------------------------
            (0)  |           (5.1)  ^                | (3)
         {Model  |        {Op Msg}  |                | {View, Op Msg}
          ,Msg}  |                  |                v
                              -------------------------- 0..* Clients (all sharing Model state)
                              |                        | 
                              |   Some Model Client    | 
                              |                        | 
                              |   Asynchronous Event   
                              |     | (4.1)      :     Relation between Client Events
                              |     v            :     and Op Msg is defined by View
                              |   View ------> Op Msg  object (created by view function)
                              |                         
                              |                        | 
                              --------------------------                                                     

		==> (0) The run-time is called with the initial Model and Msg (to get things started)

		==> (0.1) After 0 - initial update with init value {Model, Msg} (defined Model and Msg = msg_1…msg_n}

		==> (1) update returns new model state (persistent data structure = new instance) according to Msg
		==> (1.1) After 1 if Cmd Msg - recurse update with Msg (enables update to iterate with itself with internal Cmd Msg)
		==> (1.2) After 1 if No Cmd Msg - calls view function (To create a View of current Model)
		==> (2) view returns new View Op (a Client representation of current model state update)

		==> (3) run-time sends View Op  to Client

		==> (4.1) Asynchronous - Client acts on some event and calls View to create appropriate Op Msg response.
		==> (4.2) Asynchronous - run-time calls subscriptions is to get any external pending events as Sub Msg.

		==> (5.2) After 5.1, The Client returns Op Msg generated by View object in response to Client Event.
		==> (5.2) After 4.2, subscriptions returns any received external event as Sub Msg.

		==> (6.1) After 5.1 - updates model according to Msg received from Client
                       (6.2) After 5.2 - updates model according to any Msg in Sub Msg from subscription (external event receiver)
