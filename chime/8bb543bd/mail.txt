Consider it could be a good idea to model a cache of function composition call result as a path of cached values arg->arg->arg->result?

1) Consider caching the result of calling one function is arg->result?

	==> Consider f: int -> int; f x = x+2;
	==> Calling it with 3 would yield f 3 => 5
	==> We can cache this result as pair {3,5}

2) Now consider caching the result of calling the composition of two functions g f?

	==> Consider g : int -> int; g y = y*y;
	==> Composing it with f (above) would yield g o f: int -> int -> int
	==> And g o f x = g (f x) = (x+2)(x+2)
	==> So g o f 3 => g 5 => 25.
	==> And caching the result of g can be done as {5 25}
	==> But f 3 is already cached so g o f 3 can be cached as {3 5 25}

3) It seems we can thus cache calls to function compositions as paths of arg->arg->result?

	==> Each adjacent nodes in the path can be seen as the cache of one function arg->result cache?
	==> Thus the cache for g o f on x = 1…5 can be modelled as the paths:

		{1 3 9} 
		{2 4 16}
		{3 5 25}
		{4 6 36}
		{5 7 49}

	…

4) Consider that the cache paths will be tuples of values of different types (as functions may map argument type to different result type)?

	==> Consider f: int -> double and g: double -> [double]
	==> Then the cached path will be values of type {int, double, [double]}

5) Consider the meta-value path will model the function composition types?

	==> As each adjacent node in the path is the arr->result cache for a function,
	==> It follows that each adjacent node types will be the signature of a function Fn: arg_type -> result_type.
	==> And so the meat-path will be type->type->type.

	==> Consider the meta-meta cache path would be type-constructor->type-contructor->type-constructor?
	==> Consider we can use this to apply type conversions on the cache path?

		==> Consider it is the type-constructor that ”knows” how to create a type from another type?
		==> E.g., the type-constructor for float may define a constructor that accepts an integer (in effect defining int->float conversion)?
		==> Then the meta-path int->int->int may be used to instantiate the meta-path float->float->float?
