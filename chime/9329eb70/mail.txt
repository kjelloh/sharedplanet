5) Consider to study parsing terminology to get some background to understand parsing?

	==> An Abstract Syntax Tree (AST) leaves out details in the “real” syntax (e.g. parenthesis, if-keywords an C++) (https://en.wikipedia.org/wiki/Abstract_syntax_tree <https://en.wikipedia.org/wiki/Abstract_syntax_tree>)
	==> A Concrete Syntax Tree (CTX(?) or just Syntax Tree) keep all the details of the passed input (https://en.wikipedia.org/wiki/Parse_tree <https://en.wikipedia.org/wiki/Parse_tree>)

	==> The Syntax Tree is made up of nodes being root or branch (non-terminal) and leaf (terminal) “functions" (https://en.wikipedia.org/wiki/Terminal_and_non-terminal_functions <https://en.wikipedia.org/wiki/Terminal_and_non-terminal_functions>)

6) Seems OPrime for each layer shall map a range to an ordered set of ranges AND a Syntax Tree of ID:s?

	==> Each node has an ID and refers to the range in the input of the match.
	==> Sub-nodes will thus always refer to sub-ranges of the parent node range.
	==> All ranges are ranges of the same Code Points (e.g. char/octet, UCS/32-tet)

	==> Each new iteration will now create a new Syntax Tree for each mapped output range of the level before!
