Could it be a good idea to not parse C++ code to decompose it but rather divide-and-compile until the smallest compile-able parts are found?

1) Consider we would like to partition C++ code to store the parts to build the code rather than store the actual source files?

	==> In this way we would be able to re-arrange these parts for efficiency in building the code?
	==> It could be seen as an alternative to using C++ modules (proposed for C++17)
	==> Instead source is represented as trees of compile-able parts put together at compile time (just in time)?

2) Consider a divide-and-compile algorithm that uses binary search putting in a ‘;’ to identify statements?

	==> A header file may be divided in half and a ‘;’ is written there.
	==> If the first half compiles without the second one, then the first one is a source-code “statement”.
	==> If not, try to put the ‘;’ at the half of the second half.
	==> Repeat until a first compilable first “statement” is found.

	==> Now repeat the procedure on the first and second half.

		==> Note that the second half always depends on all that precedes it (for now)

	==> When no smaller parts are found we have identified all statements of the code?
