2) Consider how we may organise the source code project to build and run for different targets with different Ux models (e.g. Console versus Windows based)?

	==> It seems we need different build tool chains as well as source code conditioned for the target?

	a) Consider we can model the till chain as a build function that defines a mapping of source code to executable code?

		build: project source code -> target executable code

		==> Consider that “build” may be cerated with cmake (to get at the appropriate build tool-chain for the target we are building for)?

		cmake: CMakeLists.txt -> build

	b) Consider we can model the conditional code as a pre-process function that defines a taping from project source code to target source code?

		pre-process: generic source code -> target source code

		==> Consider this is part of the build mapping?

		build: pre-processor -> generic source code -> compiler -> target source code -> compiler-switches ->target executable code

3) Consider ways to organise the project files and directory structure to support different target source code generation and tool chains?

	==> It seems we actually have four different aspects to mirror in the directory structure?

		==> We want to allow different IDE:s (thus IDE:s specific files should go into directory structure in some controlled way)?
		==> We want to allow for at least one build tool chain generator (e.g. inject cmake files into the project file structure)?
		==> We want to allow the generic source code to contain conditionals to enable generation of different target source code (e.g., using pre-processor macros)?
		==> We want to be able to invoke different tools chains separately (e.g., build with Xcode on OS X and Visual Studio on Windows)?

	==> Consider most build tool chains allows their files to be placed separated (e.g. in parallel folders) from the source code and resource files?

		==> Consider cmake recommends the build tool chain to be generated in a separate (often a build parallel folder)?
		==> But cmake projects often place the CMakeLists.txt at the top of the source code folder structure?
