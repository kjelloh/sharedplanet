	==> This would seem to mean that meta and defacto are Functors that preserves the Algebra between a Value and a Meta-Value Category?
	==> Thus each Value on each Meta-level forms a Category and functors “meta” and “defacto” maps between Category Pairs {Value, Meta-Value}?

	==> Lets try it!

		==> Consider the Functor definition (https://en.wikipedia.org/wiki/Functor <https://en.wikipedia.org/wiki/Functor>)?

Let C and D be categories <https://en.wikipedia.org/wiki/Category_(mathematics)>. A functor F from C to D is a mapping that[3] <https://en.wikipedia.org/wiki/Functor#cite_note-3>
associates to each object X in C an object F(X) in D,
associates to each morphism f: X -> Y in C a morphism F(X): F(f): F(X) -> F(Y) in D such that the following two conditions hold:
F(Id<X>) = Id<F(X)> for every object X in C,
F(g . f) = F(g) . F(f) for all morphisms  and f: X -> Y, g: Y -> Z in C.
That is, functors must preserve identity morphisms <https://en.wikipedia.org/wiki/Morphism#Definition> and composition <https://en.wikipedia.org/wiki/Function_composition> of morphisms.
		==> Try this on meta and defacto as functor between the int type and int values?

Let IntValue and IntType be categories. A functor meta from IntValue to IntType is a mapping that
associates to each value v in IntValue, a meta-value meta(v) in IntType,
… NO, this does not work (meta is not a mapping between each int value to an int-type)!

		==> Instead, try this on meta and defector as functor between Values and Types?

Let Values and Types be categories. A functor meta from Values to Types is a mapping that:
associates to each Set of values V in Values, a Set of types meta( V) in Types
…No, this does not work either (The morphism Values -> Types does NOT preserve the structure, it maps a Set, say set of int values,  to a Singleton, say the int type)?

	==> Hm… It seems we need to understand the rations between Tha meta-levels better?
