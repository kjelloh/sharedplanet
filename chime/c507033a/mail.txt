5) This seem like a good Haskel tutorial Repl (https://www.tryhaskell.org <https://www.tryhaskell.org/>)?

	==> Haskel seem to use ”normal” algebra syntax?

12
:: Num a => a
λ 

		==> ”:: Num a => a” seem to be the type of the expression (whatever Num a means)

	==> It seems ”=>” separates a constraint from the type (i.e. a constraint on the type) (http://learnyouahaskell.com/types-and-typeclasses)?

ghci> :t (==)  
(==) :: (Eq a) => a -> a -> Bool  

		 ==> Thus ”==” is a function any-type a -> any-type a -> Bool (But a must be from the Eq class)?

”Everything before the => symbol is called a class constraint. ... The type of those two values must be a member of the Eq class (this was the class constraint)."

		==> NOTE: Elm does not seem to have this ability to express type constraints?

	==> A string literal seems to default to char array [Char] (called a list)

	==> Haskel seems to have special syntax to bind a name to a value and then use it in an expression?

	==> Haskel seems to support pattern matching (values bound based on same topological position)?

	==> Haskel seem to define pattern matching using deconstruction (based on construction pattern)?

”Values are pattern matched, or deconstructed, by writing however they were constructed.”

		==> This would mean - in our meta-lisp we could pattern match by asking for the meta-value of a defined value and a declared value?
