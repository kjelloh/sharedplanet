	==> He seems to define ”Persistent” as meaning that when we modify the structure into a new one, the old one persists?
	==> It seems this means we may implement immutable structures by having the new structure share the persistent un-changed structure?
	==> Implementing structures as DAGs (Directed Acyclic Graphs) means any new structure will have a new root node anytime we changed the structure (we have to create new copy of teh changed node and that change propagates all teh way to the root).

		

		==> Right lemon node the ”new/changed” one.
		==> Parent green nodes are new to accommodate referencing the new changed node (leaving the blue original structure persistent)
		==> Yellow nodes are shared structure and values.

	==> immutable.js seem to implemented DAGs as Tries (name from reTRIEve) and use them to implement persistent immutable Arrays and Records (although JavaScript calls records for ”Objects” = confusing)?

		==> Index Tries are DAG:s with nodes that are keys of a stored value key being the path of key-nodes to the value.
		==> In fact, given eight bit keys and four level deep Index Trie the node-path to a value with index 10001101 is the path {10,00,11,01}
		==> Thus, an Index Trie may be used to represent a list (array)

		

		==> Hash Tries are DAGs with nodes that are any type of key (e.g., a string label) but the path to the key is represented by its hash!

		

		==> In this case the path to the value with key ”R” is the hash(”R”) = 01010010 turned into index key path {01,01,00,10} but traversed in reverse order {10,00,01,01}
		==> Also, the Trie is optimized so that in this case the last key 01 si not required to idenify the ”R” node (the path {10,00,01} is unique)

		==> Thus a Hash Tries is good for key-value maps (and thus in effect to represent Records and Sets)?
