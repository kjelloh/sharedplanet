3) It seems we can animate chains of transitions by listing them (https://css-tricks.com/using-multi-step-animations-transitions/ <https://css-tricks.com/using-multi-step-animations-transitions/>)?

	==> First, its seems CSS works a little “backwards” (it defines an end-frame target values for properties and transition properties separately)?

.box {
  width: 150px;
  height: 150px;
  background-color: red;
  transition: 1s;
}

.box:hover {
  width: 300px;
  background-color: orange;
}
		==> This seems to mean that “on hover” the width shall change to 300 and background-color to orange?
		==> BUT: In “.box” the transition is set to 1 second duration.
		==> So - The CSS rendering interprets this as when making the transition from “.box” initial values to “.box:hover” values it shall animate the transition over 1 second?

	==> Further, if we define the transition property to be a list, then we get a multi-step transition (each transition defining what proper values to “animate”=

...
transition: 
    /* step 1 */
    width      1s,
    /* step 2 */
    background 0.5s 1s;
}

.box:hover {
  width: 300px;
  background-color: orange;
}

		==> Now “on hover” will execute the transition where the “width” property first animates to 300 over 1 second.
		==> And then - the background color animates to orange over one second (with 0.5 seconds initial delay)

	==> This implicit “transition” function and parameters is a little odd?
