For some reason InstallShield Express 2012 crashes when signing the msi-file using a spc and pvk code signing files. So consider to create a pfx-file to use instead (a pfx-file may be created to carry both the certificate and the private key needed to sign files).

1) A good page on file endings and formats seems to be https://support.ssl.com/Knowledgebase/Article/View/19/0/der-vs-crt-vs-cer-vs-pem-certificates-and-how-to-convert-them  
2) Seems we should use the openssl pkcs12 command to create the pfx-file? (https://www.openssl.org/docs/manmaster/apps/pkcs12.html)  
3) SSLShopper suggest how pkcs12 shall be used (https://www.sslshopper.com/ssl-converter.html)

Convert PEM to PFX  
&gt; openssl pkcs12 -export -out certificate.pfx -inkey privateKey.key -in certificate.crt -certfile CACert.crt

Convert P7B to PFX  
&gt; openssl pkcs7 -print_certs -in certificate.p7b -out certificate.cer  
&gt; openssl pkcs12 -export -in certificate.cer -inkey privateKey.key -out certificate.pfx -certfile CACert.cer

==&gt; Windows seem to indicate that the spc-file I got from GoDaddy is a p7b-file (thus I need do the convert-to-cer step).  
==&gt; And what is the CACert.cer file?

4) In my case I have an spc-file which windows claims to be a PKCS #7 file.

I tried SPC to PFX  
&gt; openssl pkcs7 -print_certs -in d8775b727123848b.spc -out d8775b727123848b.cer  
&gt; openssl pkcs12 -export -in d8775b727123848b.cer -inkey privateKey.key -out d8775b727123848b.pfx -certfile CACert.cer

==&gt; No, "openssl pkcs7 -print_certs -in d8775b727123848b.spc -out d8775b727123848b.cer" failed. d8775b727123848b.spc is NOT a p7b-file.

5) I tried using windows export function to create a p7b-file from my spc-file.

a) I opened the spc-file, and then the ITfied certificate.  
b) I used the &lt;Save File&gt; option and selected “Exported as p7b” and “include all certificates in the path”.  
c) I saved it as TheITfiedCert.p7b

Now I tried P7B to PFX  
&gt; openssl pkcs7 -print_certs -in TheITfiedCert.p7b -out d8775b727123848b.cer  
&gt; openssl pkcs12 -export -in d8775b727123848b.cer -inkey privateKey.key -out d8775b727123848b.pfx -certfile CACert.cer

==&gt; NO, “openssl pkcs7 -print_certs -in TheITfiedCert.p7b -out d8775b727123848b.cer” still does not work!  
==&gt; “unable to load PKCS7 object 1424:error:0906D06C:PEM routines:PEM_read_bio:no start line:.\\crypto\\pem\\pem_lib.c:703:Expecting: PKCS7”.

i) According to this link (http://support.citrix.com/article/CTX124429/) it seems openssl is unable (?) to read p7b-files generated by windows?  
ii) The solution seems to be to use windows to create a pem formatted file of the certificate instead?

6) So I tried to use a cer-certificate created by windows instead.

a) I opened the spc-file and saved the ITfied certificate as “Base-64 encoded”, i.e. PEM-format.  
b) I named the file TheITfiedCert.cer

I now tried PEM to PFX  
&gt; openssl pkcs12 -export -out certificate.pfx -inkey privateKey.key -in TheITfiedCert.cer

\*) Note no -certfile parameter (I trusted openssl to get it from windows CA storage).

==&gt; The command created a pfx-file (although it reported “Unable to write ‘random state'”). What does that mean?  
==&gt; The created pfx-file was accepted by InstallShield!
