1) Consider to elaborate on the point that a File and a Folder are just composites in the tree of objects in the File System?

2) Consider to elaborate on the benefits of identifying more data objects that conforms to the same Composite Data Model as a File System?

	==> Consider the Windows Registry?
	==> Consider an XML-file?
	==> Consider an HTML-file?

3) Consider the problem of self-referencing members of Composite Data Models?

	==> Consider a member referenced by another member actually has two paths to the same element?
	==> Consider this is the “problem” of file “short-cuts” (A file that is actually a proxy for another file/folder)?
	==> Consider the problem of circular references (e.g. a file short-cut to a folder that aggregates the short-cut in its sub-tree)?

4) Consider allowing mixing aggregated and referenced objects is the root to the problem of modelling composite data models?

	==> If only aggregated members where allowed all Composite Data Models would be top-down structures of single-instance members?
	==> Allowing references as proxies for “real” instances confuses what path to an element is the “real” one (and what the effects of mutating a member are)?
	…

5) Consider allowing references introduces the problem of Identity and Ownership?

	==> Consider allowing references means the key-path to the element is not enough to identify the element?
	==> Consider allowing references introduces the problem of deciding what Element Deletion means (deleting a proxy has no effect as the referenced element must remain)?

	==> Consider file references actually introduces exactly the same problems as pointers and references in computer programming?
