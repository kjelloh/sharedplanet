4) Consider to read the ”original” Monad paper (http://homepages.inf.ed.ac.uk/wadler/papers/marktoberdorf/baastad.pdf <http://homepages.inf.ed.ac.uk/wadler/papers/marktoberdorf/baastad.pdf>)?

	==> Also reachable through bit.ly/monad-paper <http://bit.ly/monad-paper> 

	==> It seems it defines a Monad type M quite good!

”The original evaluator has the type Term → Int, while in each variation its type took the form Term → M Int. In general, a function of type a → b is replaced by a function of type a → M b. This can be read as a function that accepts an argument of type a and returns a result of type b, with a possible additional effect captured by M. This effect may be to act on state, generate output, raise an exception, or what have you."


		==> Replace ”plain” function a —> b with a function a —> M b (i.e., the monadic value of b)

	==> And the monadic type M must be able to do two things to accomplish this.

”First, we need a way to turn a value into the computation that returns that value and does nothing else.

unit :: a → M a"

”
Second, we need a way to apply a function of type a → M b to a computation of type M a. It is convenient to write these in an order where the argument comes before the function.

(⋆) :: M a → (a → M b) → M b"

	==> The Monad may then be defined.

”A monad is a triple (M,unit,⋆) consisting of a type constructor M and two operations of the given polymorphic types.”

==> (1) We must be able to construct the type M (in C++ we use a template for this, e.g., the template ”Maybe” and we construct the Monad type with Maybe<Handle>, Maybe<string> etc…)
==> (2) We need the ”unit” where we may instantiate the monadic value given the ”plain” value (In C++ we may call the constructor, e.g., Maybe<Handle>(handle), Maybe<string>(”Hello”)…)
==> (3) We need a function that uses the a —> M b to turn M a to M b.

	==> This function is created by bind!
	==> Q: But where do we get our a —> M b?
