1) Consider the Tha modelling of “normal” value-functions (type mappings)?

	==> Consider a value-function maps values form one type to values of another type?

	value_f: type_1 - > type_2

	==> Consider a function declaration binds a name to an instance of the function argument environment?

	int f(int x);

	   type: “_” ----> {{“x”, “int", null}, {“_”,”int", null}} // type: int -> int
                  ^
                  |
	  value: “f” ----> null // name “f” not yet defined = no body

		==> Thus, the function type can be modelled as an environment listing the mappings x -> y -> z (the last binding is the return meta-value declaration)?

	==> Consider a call to a declared function instantiates a “call environment” and binds provided arguments in this call environment?

	int f(int x) {
	    return x*x + k;
	}
	void main() {
	    int a;
	    int y = f(a); // binds “k” to call environment (stack frame)
	}
