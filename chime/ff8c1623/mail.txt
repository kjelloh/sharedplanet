Can we imagine a Gateway between two state machines to work just on listening to state transitions in the two state machines?

1) Consider an upstream iPos fsm (finite state machine) and one downstream Epas fsm.

	==> The upstream iPos fsm acts on upstream received iPos messages and changes state accordingly.
	==> The Downstream Epas fsm acts on downstream received Soaps messages and changes state accordingly.

	==> Now, can a gateway perform iPos <-> Epas event transforms based only on the state changes of these two state machines?

	upstream —> msg —> iPos FSM —> Transition —> Gateway <— Transition <— Epas FSM <— msg <— downstream

	==> Now, it is evident that in this model the Gateway has no means to trigger events in the two state machines.

	upstream <— msg <— iPos FSM <—  Event <— Gateway —> Event —> Epas FSM —> msg —> downstream

	==> Now, is this sufficient for all processing we need to do to transfer messages both up- and down-stream?

	upstream —> msg —> iPos FSM —> Transition —> Gateway <— Transition <— Epas FSM <— msg <— downstream
												  ^
												   |
												  v
	upstream <— msg <— iPos FSM <—    Event  <—    Gateway      —> Event  —>  Epas FSM —> msg —> downstream


	==> Now we may have an upstream msg received by iPos FSM trigger a state transition that the Gateway turns into an Event to the Epas FSM that will send its message.
	==> And vice versa a downstream message received by Epas FSM may trigger a state transition that the Gateway turns into an Event to the iPOS FSM that will send its message.

	==> The key design will then to ensure each received message triggers sufficient state transitions so have the Gateway trigger the message transform.
